# Canvas v51.22: Code Tidy

- **Date:** 2026-10-17
- **Goal (one line):** clean the code and make the rules checkable, with **no visible change anywhere**.
- **Start:** a new branch from an up-to-date main (v51.21 merged), e.g. `claude/v51-22-tidy`. A new workstream, so a fresh Code session.
- **Pull request title:** `Canvas v51.22: Code tidy`

## 1. Context

The first independent eval (17 Oct, at v51.16) found the code had fallen behind its own rules: about 700 lines of
leftover state and calculations in League.js from tabs that moved to LeagueTabs.js, rules that live only in the
handoff (the kit can't fail a build on them), no code checker, two empty-save leaks, and file-header changelogs that
make up about 10% of the code. This build cleans that up. It is the first of two tidy builds: v51.23 will handle
index.html and compiling Tailwind ahead of time. **Nothing on screen may change.**

The user's rule for removals applies: report line counts before and after. A removal that doesn't shrink the file
didn't happen.

## 2. Scope

- **Files:** every file in `src/` (changelog move; rules fixes where League, LeagueTabs or ui.js break a rule),
  `src/League.js` (the leftovers), `src/App.js` (the unused row-shift parameter), `test/` (rules check, lint,
  empty-save check, small-text baseline), `CHANGELOG.md` (new), `CLAUDE.md`, `briefs/TEMPLATE.md`.
- **Not in this build:** `public/index.html` and Tailwind (v51.23); Cups, Pyramid and Squad behaviour (their rule
  breaks are listed as debt, fixed when each page converts); hook dependency changes (see 3c).

## 3. What to build

### 3a. Delete League.js's leftovers

1. **Remove everything in `League.js` that no live code reads:** the state, memos and helpers left behind when
   Spider, Home vs Away, Points and Form & Margins moved to LeagueTabs.js. The eval named, among others:
   `outliersAndExtremes`, `activeHomeAway`, `seasonMargins`, `getBadgeDetails`, `droppedSummaryKPIs`,
   `moveFloatingTooltip`, `LeagueTierBar`, `MarginCell`, `formatClearance`, `MD_SCOPES`, `MD_SORTS`, `PULSE_WINDOW`,
   `ENABLE_EDITING`, the `useState('RMA')` / `'BAR'` / `'PSG'` defaults and about 18 unused icon imports.
2. **Prove it before deleting:** for each removal, show that nothing reads it (search plus the linter's unused list).
   Anything something still reads stays, and is named in the report. The eval asked whether the old layer was kept on
   purpose (does anything still read `clubs`, `seasons` or `rowsByIndex` from it?); answer that question in the report.
3. **The unused row shift in App.js:** `shiftRows` copies every row of the active sheet on every render while
   `rowShift` is 0 for all four pages. Remove it.
4. **Report:** line count, `useState` count and `useMemo` count of `League.js` and `App.js`, before and after.

### 3b. A rules check in the kit

5. **`test/rules.js`, run as part of `npm run check`.** It scans `src/` and fails the build with file and line for:
   - `window.innerWidth` / `window.innerHeight` (use `useScreen()` or Tailwind);
   - `(hover: none)` (touch is decided by the pointer type);
   - any club's name or abbreviation as a string in code (the list comes from the sheet's club directory in
     `sheetData.js`, so it never needs typing);
   - `useState('<club abbreviation>')` defaults;
   - typed-in counts: the literals 91 and 92 used as club counts, season loops to a fixed number (`<= 15`),
     `GAMES_PER_SEASON`-style tables;
   - a plain `overflow-x-auto` row that isn't a listed wide table (chip and switch rows use `ScrollRow`).
6. **Allowed exceptions** live in one file (`test/rules-allow.json`), each with its file, the rule and a reason. Two
   kinds only: (a) the one place a rule is implemented (for example, inside `useScreen()` itself); (b) **page debt**
   in Cups, Pyramid and Squad, marked with the page name, cleared when that page converts.
7. **Fix every break in League.js, LeagueTabs.js and ui.js now** (the eval counted `window.innerWidth` in
   LeagueTabs.js at lines 186–187, League.js and ui.js, and `(hover: none)` in League.js). After this build, League
   has no exceptions except where a rule is implemented.

### 3c. ESLint

8. **Add ESLint** (with the `react` and `react-hooks` plugins) to the test kit's own dependencies, not the app's; add
   `npm run lint` and run it inside `npm run check`.
9. **A lint baseline,** not a lint purge: record each file's finding count in `test/lint-baseline.json`. The check
   fails if any file's count goes up. Counts go down as pages convert.
10. **Fix only the safe findings in this build:** unused names (most go with 3a), missing `key` props in files this
    build touches. **Do not change any hook's dependency list:** adding a dependency changes when a calculation
    re-runs and can change behaviour. List every dependency warning in the report instead.

### 3d. Empty save

11. **Two leaks the eval found:** Seasons' Highlights bar prints "NaN G/M" with no matches; Points prints a bare
    "null" with no seasons. With no data, a number shows "—" and nothing prints "null", "undefined" or "NaN".
12. **A permanent empty-save check in the kit:** render every page and tab against an empty workbook and a
    headers-only workbook; fail on a React error or on "NaN", "undefined", "null" or any club name in the visible text.

### 3e. Small-text baseline per page

13. **Replace the single sub-11px total (1,524) with a per-page, per-tab count** in `test/baseline.json`. The check
    fails if any page's or tab's count rises; a touched page should bring its own down over time.

### 3f. CHANGELOG.md

14. **Move every file's changelog into one `CHANGELOG.md`** at the top level: grouped by canvas version, newest
    first; each entry names its files and keeps its wording. Nothing is dropped.
15. **Each file keeps a short header:** file name, its version, date and time (UTC), one line on its latest change,
    and "History: CHANGELOG.md". `VERSION_TAG`, `PUBLISHED` and the footer version line work exactly as now.
16. **From now on** each build adds its entry to `CHANGELOG.md` and bumps the file headers; the pull request
    description carries the build report as before.

## 4. Rules that apply

- **Ask before changing a convention:** this build changes three (the rules check, the lint baseline and
  CHANGELOG.md), all agreed with the user on 17 Oct. Nothing else.
- **Club-agnostic, no typed-in counts, `useScreen()`, touch by pointer type:** this build makes them checkable.
- **Hover cards, ScrollRow, flags, minus signs, curly apostrophes:** unchanged from v51.19–v51.21.

## 5. Must not change

- **Anything on screen, on any page, tab, mode or size, light or dark.** This is a tidy build: if a screenshot
  changes, it's a bug.
- Every interaction, hover card, tap behaviour, sort, filter and drawer.
- The version line in the footer (apart from the new numbers).

## 6. Checks before the pull request

- **Pixel comparison:** before / after screenshots of every page and tab at 390 and 1440, light and dark (the
  R0-style sweep). Report any page with any difference, and why. The target is zero.
- **Test kit:** `check` (now including compile, rules, lint, empty save and the per-page baseline), `css`, `bundle`,
  `overflow`, the tap test (sample on every tab), the fade sweep, `pts_t`, `spider_t`, `ha_t`. All pass.
- **Numbers in the report:** line, `useState` and `useMemo` counts for League.js and App.js before and after; total
  `src/` lines before and after; lint findings per file (the new baseline); rule exceptions per page; how many lines
  moved to CHANGELOG.md.
- **Prove the new checks work:** in a scratch commit you don't push, add one `window.innerWidth`, one club name and
  one sub-11px label to LeagueTabs.js and show each check fails; say so in the report.
- **Previews:** the Netlify deploy preview builds; its link goes in the pull request.

## 7. Updates in the repo

- Every changed file's header (short form, 3f); `App.js` version line "Canvas v51.22 …" and `PUBLISHED`; brief saved
  as `briefs/v51.22.md`; `CHANGELOG.md` gets the v51.22 entry.
- **CLAUDE.md:** the rules check, the lint baseline, the empty-save check and the per-page baseline in the checks;

## Decisions taken with the user before the build (18 Oct)

- A third exception kind, "same letters, not a club" (country codes such as ESP or POR, words such as "Standard"),
  with abbreviations matched in capitals only.
- The League season stepper (ui.js ScopeStepper) and the Top Bar page links stay plain sideways rows for now, listed
  as "standards review" exceptions, because converting them adds visible edge fades.
- League.js's live typed-in counts (games per season, the 91-club limit) are derived from the sheet now, proven to
  give the same results on today's data.
