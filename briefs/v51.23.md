- **Date:** 2026-10-18
- **Goal (one line):** the page loads like a normal website: a proper HTML structure and Tailwind compiled ahead of
  time instead of in the visitor's browser. **Nothing on screen may change.**
- **Start:** a new branch from an up-to-date main (v51.22 merged), e.g. `claude/v51-23-page-build`, in the
  tidy-workstream session.
- **Pull request title:** `Canvas v51.23: Page build`

## 1. Context

The second tidy build, from the first independent eval. Today `public/index.html` has no `<!doctype>`, `<html>`,
`<head>` or `<title>`: it starts with a comment and leaves the rest to the browser. And Tailwind runs as the "play
CDN": every visit downloads the Tailwind compiler and builds the stylesheet inside the visitor's browser, which costs
most on a phone. The user chose the small step (17 Oct): compile Tailwind ahead of time inside the existing
react-scripts build; moving to Vite stays a later decision. The page also downloads Playfair Display, which only the
hidden Lab bar uses.

This build changes how the page loads, not what it shows. **Rollback:** if anything looks wrong after merging,
reverting this one pull request on GitHub restores v51.22 exactly.

## 2. Scope

- **Files:** `public/index.html`, `package.json` (pinned Tailwind), new `tailwind.config.js` and `src/index.css`,
  `src/index.js` (imports the CSS), `src/ui.js` only for the Playfair item, `test/css.js` (uses the same config),
  `App.js` version line, `CHANGELOG.md`, CLAUDE.md.
- **Not in this build:** Vite, any visible change, any component.

## 3. What to build

### 3a. A proper page structure

1. `public/index.html` becomes a standard document: `<!doctype html>`, `<html lang="en">`, `<head>` with
   `<meta charset="utf-8">`, the existing viewport tag, `<title>GSL Canvas</title>`, the font preconnects and
   stylesheet, and the existing `<style>` block; then `<body>` with `<div id="root"></div>`. The file's header
   comment moves inside `<head>`, and still never contains a literal html tag (the v51.18 rule).

### 3b. Tailwind compiled ahead of time

2. **Remove the play CDN** (`<script src="https://cdn.tailwindcss.com">`) and the inline `tailwind.config` script.
3. **Add Tailwind as a build step** of the existing react-scripts build (react-scripts 5 runs Tailwind through PostCSS
   when a config file is present): `tailwindcss` pinned to the 3.4.x the CDN serves today (exact version, no range),
   a top-level `tailwind.config.js` and `src/index.css` with the three `@tailwind` lines, imported once in
   `src/index.js`.
4. **One config, used everywhere.** `tailwind.config.js` carries what the inline script did: every colour family
   (slate … rose) and shade (50 … 950) as `rgb(var(--c-<family>-<shade>) / <alpha-value>)`, and
   `fontFamily.sans: ['var(--font-text)']`; `content` points at `./src/**/*.js` and `./public/index.html`. The test
   kit's `test/css.js` must use this same file, so the kit and the live site can't drift apart.
5. **Class names built at runtime.** The play CDN sees the finished page, so it styles class names assembled in code
   (for example `` `bg-${tone}-500` ``); an ahead-of-time build only sees whole class names written in the source.
   Find every such case: compare the classes in the kit's snapshot-based CSS with a source-only build, and list the
   difference. For each, prefer writing the full class names into the code; otherwise add them to a `safelist` in
   the config with a comment saying where they're used. Report the list.
6. **Order of styles stays the same:** wherever index.html's own `<style>` rules relied on loading before or after
   Tailwind, keep that order; the pixel comparison (section 6) is the proof.

### 3c. Playfair only with the Lab

7. Remove Playfair Display from the font download. If `SHOW_LAB_BAR` is ever switched back on, `LabBar` adds the
   Playfair stylesheet itself when it mounts, so the Lab's "Playfair Display 600" option keeps working. The locked
   fonts (Lexend, Outfit, Atkinson Hyperlegible Next) load exactly as today.

## 4. Rules that apply

- **Ask before changing a convention:** this build changes how styles are produced, agreed with the user on 17 Oct
  ("small step now, Vite later"). Nothing else.
- **No literal html tag inside an index.html comment** (v51.18). **Exact version pins**, never ranges or "latest".
- Every existing rule and check from v51.17–v51.22 still applies.

## 5. Must not change

- **Anything on screen, on any page, tab, mode or size, light or dark,** including the Lab bar staying hidden. If a
  screenshot changes, it's a bug.
- Dark mode switching (the `--c-*` colour variables), fonts, hover cards and tap behaviour.
