## 1. Context

The owner can't review code, and the builder, the design chat and the independent evaluator are all Claude models
with shared blind spots. On 18 Oct the user and the design chat agreed five review layers, arranged so their holes
don't line up: (1) Code and the design chat hold each other to account through a shared flags log; (2) the user's
on-device review, sized to the change; (3) GitHub checks that stop bad code; (4) a milestone review with golden
numbers; (5) a firewalled independent eval. This build puts layers 1–4 into the repo. The full design is in the living
handoff, section "Review layers". It's a pilot: about 10 pull requests or 3 days, reviewed at v51.35.

## 2. Scope

- **New:** `FLAGS.md`, `.github/pull_request_template.md`, `.github/workflows/` (the checks), a root
  `package-lock.json`, `test/golden.json` and its check, a future-save fixture in `test/`.
- **Changed:** `package.json` (exact versions), `netlify.toml` only if `npm ci` needs it, the test kit (real icons, new
  checks), `CLAUDE.md`, `README.md`, `test/README.md`, `briefs/TEMPLATE.md`, `App.js` version line, `CHANGELOG.md`.
- **Not in this build:** any visible change; any `src/` change other than the version line (if a check finds a real
  bug, list it as a flag, don't fix it here).

## 3. What to build

### 3a. FLAGS.md (layer 1)

1. A top-level `FLAGS.md`: one entry per flag, newest first, each with a number (F1, F2 …), title, raised by (Code /
   design chat / the user / eval), date, status (open, fixed, accepted, rolled back), and where it was resolved (pull
   request or version). Kept by Code; the design chat's flags arrive in a brief's "Carry-over flags" section and Code
   copies them in. No secrets or personal details (the repo is public).
2. **Start it with these carry-over flags** from the design chat (all from 17–18 Oct):
   - **F1, open:** Opponents Highlights "Most played" names one club (Arsenal) when 14 clubs tie at 10 games: the tie
     is broken alphabetically, silently (League.js, Opponents highlights). Design decision pending.
   - **F2, open:** "Best record" and "Toughest opponent" break ties silently (by goal difference).
   - **F3, open:** Home vs Away has two separate Points / Wins / Goals switches (Venue swing, Venue ledger) that don't
     follow each other. Decision pending.
   - **F4, open:** Venue swing season columns are about 35 × 260px on phones (under 44px wide); decision pending.
   - **F5, accepted:** Points heat-strip cells about 5px wide; read by sliding. **F6, accepted:** the last ledger rows
     can't be centred by "See in ledger".
   - **F7, open:** black or navy club colours vanish on the dark card (Spurs, Juventus, Leverkusen): the
     secondary-colour pass.
   - **F8, accepted exception:** emoji as controls in Squad Interactions (a vector redraw preferred later) and the
     coming squad role system.
   - **F9, accepted:** StackBlitz may show branches unstyled since v51.23 (previews run on Netlify).
   - **F10, open:** 22 hook dependency warnings (lint baseline), listed, never checked one by one.
   - **F11, accepted:** two "ESP" chips on Cups Finals sit up to 1px off; Cups Competitions' right column 1px lower
     (v51.24).
   - **F12, open (standards review):** the Top Bar page links and the Matchdays season row scroll sideways without edge
     fades.
   - **F13, open:** HighlightCard turns `text-white…` into `text-white-undefined` (not a class; the icon falls back to
     grey). Found in v51.23.
   - **F14, fixed in this build:** the kit drew icons with a stand-in, not the real icon library (v51.24).
3. Every pull request description lists the flags it opened, closed or touched.

### 3b. Pull request template and the checklist gate (layer 2)

4. **`.github/pull_request_template.md`** with: Netlify preview link; size (Invisible / S / M / L); "The user's checks"
   as tick-boxes (copied from the brief); what's in; beyond the brief and why; checks run with results; flags opened /
   closed; what was not checked; rollback (required for L).
5. **The checklist gate:** a GitHub check that fails while any box under "The user's checks" is unticked, and passes
   once all are ticked (re-running when the description is edited). It reads only that section.

### 3c. GitHub checks (layer 3)

6. **Workflows in `.github/workflows/`, running on every pull request** (and on pushes to `main`), each a separately
   named check, so the user can require them by name:
   - **Kit:** `npm run check` (syntax, compile, doctype, rules, lint baseline, render, small-text baseline, empty save,
     golden numbers).
   - **Browser:** `css`, `bundle`, `overflow`, the tap test in sample mode, the fade sweep.
   - **Production build:** `CI=false npm run build` from the lockfile, exactly as Netlify builds.
   - **Safari engine:** render every page and tab of the production build in Playwright's WebKit at 390 and 1440: no
     page errors, no sideways page scroll. (The kit runs Chromium; this catches Safari-only breakage.)
   - **Checklist gate** (3b).
7. **Speed and safety:** hard timeouts on every step; nothing left running in the background; cache the installs.
   Target: all checks finished within about 10 minutes. The full tap sweep and the 120-view pixel comparison stay
   manual (`npm run tap:full`, `npm run pixel`) because they're slow; Code runs them when a brief asks.
8. **Permissions:** read-only (`contents: read`), except what the checklist gate needs to read the pull request. No
   secrets.

### 3d. Lockfile

9. **Commit a root `package-lock.json`** and pin every dependency to an exact version (today `d3` and `lucide-react`
   use ranges). The production build and the workflows install with `npm ci`, so every build uses exactly the same
   code.
10. If Netlify needs a setting for `npm ci`, put it in `netlify.toml`.

### 3e. Real icons in the kit

11. Switch the test kit from its icon stand-in to the real `lucide-react` (the user approved, 18 Oct; Code found it
    works once React is pinned to the kit's copy). Afterwards, kit screenshots and the production build match: report
    the kit-vs-production pixel result (expected: everything identical apart from the known run-to-run noise). Close
    F14.

### 3f. Golden numbers (layer 4)

12. **`test/golden.json` and a check inside `npm run check`.** Each entry: the value, where it appears on the canvas
    (page, tab, element), and its kind: **golden** (verified true by the user against the sheet on 18 Oct; a change
    fails the build) or **pinned** (not in the sheet; a change is reported for a look, but doesn't fail). Read the
    values **from the rendered page**, not from the code's calculations, so the check tests what ships. The user's
    list: the "GSL Canvas: Golden Numbers" doc (claude.ai).
13. **Golden (20):**

      155; titles 8 of 8.
    - S1 105 pts, 32 · 9 · 5, 98–39; S3 111 pts, 35 · 6 · 5, 113–37; S4 100 pts, 31 · 7 · 0, 85–27; S8 93 pts,
      29 · 6 · 3, 94–28; S8 title clearance +20.
    - Points at home 387, away 400; home record 121 · 24 · 19, away 124 · 28 · 12.
    - Biggest win Napoli 12–0 (S7, MD 10, home); heaviest defeat Lens 2–7 (S1, MD 4, home); wins by exactly 3 goals:
      49; longest winning run 11 (S5 MD 27 → S5 MD 37).
    - Toughest opponent Juventus, 1.90 PPG over 10 games; Matchday 34 won all 8 (33–5); points dropped 197 (104 from
      draws, 93 from defeats).

### 3g. Future-save fixture (shared hole: the future save)

15. **A synthetic workbook in `test/`** built from today's data plus: four more seasons (S9–S12, the last
    half-played), more clubs (120, including long and accented names such as "Borussia Mönchengladbach"), and a season
    in a division the save hasn't reached yet. No real club names that aren't already in the data.
16. **Render every page and tab with it at 390 and 1440:** no page errors, no sideways page scroll, no "NaN",
    "undefined" or "null". Run it inside `npm run check`.
17. **Report what breaks, don't fix it:** anything that renders but looks wrong (wraps, overlaps, colours running out
    after S8) becomes a flag in FLAGS.md.

## 4. Rules that apply

- **Ask before changing a convention:** this build adds conventions agreed with the user on 18 Oct (flags log,
  template and gate, checks, lockfile, golden numbers, future-save fixture, real icons in the kit). Nothing beyond them.
- **Test what ships:** the new checks run against the production build wherever possible, not a stand-in.
- Every existing rule and check still applies.

## 5. Must not change

- **Anything on screen.** Pixel comparison of the production build against main: 120 of 120 identical, apart from the
  known run-to-run noise.
- How Netlify previews and the live site build (apart from `npm ci` from the lockfile).

## 6. Checks before the pull request

- **Every new check proves it can fail:** in a scratch commit you don't push, break each one on purpose (an unticked
  box, a changed golden number, a page error under WebKit, a NaN with the future save, a changed dependency without the
  lockfile) and show it goes red. Report each.
- **This pull request itself runs the new workflows:** report each check's name, result and run time.
- **The pixel result** (5), **the kit-vs-production result** (3e), and **the future-save findings** as flags.
- **Netlify preview link** in the pull request.

**The user's checks (size L, invisible on screen; in the PR as tick-boxes):**

1. On the pull request page, the new checks appear and are green, except the checklist gate, which is red until these
   boxes are ticked.
2. Tick the boxes one by one: the checklist gate turns green only after the last.
3. Open the preview on your phone and click around: nothing looks different.
