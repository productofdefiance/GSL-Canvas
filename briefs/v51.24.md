- **Pull request title:** `Canvas v51.24: Doctype`

## 1. Context

v51.23 found that `public/index.html` has no doctype, so browsers draw the live site in **quirks mode**, while the
test kit, every screenshot the design chat reviewed and every approved design were drawn in **standards mode**.
Adding the doctype changes 72 of 120 views (Code's v51.23 measurements): empty icon or emoji wrappers take their full
line height (a `text-3xl` span 11px → 36px), table rows 29px → 31.5px, table text black → slate-900, Cups Rivalries
at 390 grows 648px. This build adds the doctype, so the live site matches what was designed and tested, and fixes
whatever standards mode makes look **worse than the approved designs**.

## 2. Scope

- **Files:** `public/index.html` (the doctype); any page file only where a fix in 3b is needed; `App.js` version line;
  `CHANGELOG.md`; the test kit.
- **Pages:** all (the doctype is page-wide). Fixes only where a view gets worse.

## 3. What to build

### 3a. The doctype

1. `<!doctype html>` as the very first line of `public/index.html`, before `<html lang="en">`. The header comment
   stays inside `<head>`.

### 3b. Fix what gets worse

2. **Shoot all 120 views twice from real production builds:** "before" = main (quirks), "after" = this branch
   (standards). Commit no images; list every view that differs, with what changed and by how much.
3. **Sort each difference** into: (a) **matches the approved design** (the kit always drew this, e.g. slate-900 table
   text, the 31.5px rows): keep; (b) **unintended growth or shift** (e.g. an empty icon or emoji wrapper now 36px
   tall, Cups Rivalries +648px): fix so the view keeps its quirks-mode spacing, normally by giving that wrapper
   `leading-none` or a fixed height, never by removing the doctype; (c) **unclear**: don't change it; list it for
   review.
4. **Fixes stay minimal:** spacing and line height only, in the element that grew. No redesign, no colour or font
   change, nothing on League that the phone pass approved.

### 3c. The kit and the live site agree

5. With the doctype in, the kit's pages and the production build should draw the same: run the pixel sweep **kit
   bundle vs production build** and report the result. Remaining differences are bugs to list.
6. **A permanent check:** the kit fails if `public/index.html` doesn't start with the doctype.
